# Laboratorio 4 · CD: publicar la imagen de la API

Sábado del fin de semana 2 · 75 min · por equipos · hito E4

## Objetivo
Que un merge construya la imagen de la API y la publique sola en GitHub, lista para correr en Docker Desktop. La API no se publica en internet: corre en el portátil de cada integrante. Casi todo se hace desde la página de GitHub; solo los pasos 3 y 6 usan la terminal.

Hace falta tener el [laboratorio 1](01-dagshub.md) (DagsHub) y el [laboratorio 2](02-api-docker.md) (Docker).

## Pasos

### 1. Guardar los secretos en GitHub
En el repositorio del equipo: **Settings › Secrets and variables › Actions › New repository secret**. Creen dos:
1. `DAGSHUB_USER`: el usuario de DagsHub.
2. `DAGSHUB_TOKEN`: el token de DagsHub.

Un token subido a Git queda en el historial aunque lo borren después. Si se filtra uno, revóquenlo y creen otro. Para publicar la imagen no hace falta otro secreto: GitHub le da al workflow un token propio.

### 2. Agregar el workflow
1. En **Code**, abran el menú de ramas, elijan `entrega/e4`, escriban `feat/cd-imagen` y pulsen **Create branch**.
2. Pulsen **Add file › Create new file** y en el nombre escriban `.github/workflows/cd.yml`.
3. Peguen este contenido sin cambios, que también está en [la plantilla](https://github.com/srobles5/mlops-plantilla/blob/master/labs/FDS2/workflows/cd.yml):
```yaml
name: CD
on:
  push:
    branches: [master, entrega/e4]
permissions:
  contents: read
  packages: write
jobs:
  publicar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.12"
      - run: pip install dvc
      - name: Traer el modelo
        run: |
          dvc remote modify dagshub --local auth basic
          dvc remote modify dagshub --local user ${{ secrets.DAGSHUB_USER }}
          dvc remote modify dagshub --local password ${{ secrets.DAGSHUB_TOKEN }}
          dvc pull models/model.pkl
      - name: Construir y publicar la imagen
        run: |
          IMAGEN=ghcr.io/$(echo "${{ github.repository }}" | tr '[:upper:]' '[:lower:]'):latest
          echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u "${{ github.actor }}" --password-stdin
          docker build -t "$IMAGEN" .
          docker push "$IMAGEN"
```
4. Pulsen **Commit changes...** y confirmen en esta rama.

`entrega/e4` está en la lista para poder probarlo antes de que el docente una el E4 a `master`. Cuando el E4 se una, pueden quitarla.

### 3. Confirmar que el modelo está en DagsHub (terminal)
El modelo no está en Git: el workflow lo trae de DagsHub. Quien entrenó el último modelo corre esto en su portátil, en la rama del equipo que tenga el último `dvc.lock`:
```bash
dvc push
```
Si responde que todo está al día, ya pueden seguir.

### 4. Pull Request y publicación
1. Pulsen **Compare & pull request**, con `base: entrega/e4` ← `compare: feat/cd-imagen`, y creen el PR.
2. Cuando el check `pruebas` esté en verde, otro integrante aprueba: **Files changed › Review changes › Approve › Submit review**.
3. **Merge pull request › Confirm merge**. Ese merge dispara el CD.
4. En la pestaña **Actions**, abran el workflow **CD** y esperen a que quede en verde. Tarda unos minutos.

### 5. Hacer pública la imagen (una persona)
Las imágenes nuevas quedan privadas y hay que abrirlas una sola vez. Esta imagen incluye el modelo, así que un equipo con datos propios debe avisar al docente antes de hacerla pública.
1. En la página principal del repositorio, a la derecha, abran **Packages** y luego la imagen.
2. Pulsen **Package settings**.
3. Abajo, en **Danger Zone**, pulsen **Change visibility** y elijan **Public**.
4. Escriban el nombre de la imagen y confirmen. Después no se puede volver a privada.

### 6. Correrla en Docker Desktop
Traer la imagen es el único comando; cambien `<usuario>` y `<repo>` por los suyos, en minúsculas:
```bash
docker pull ghcr.io/<usuario>/<repo>:latest
```
Después, en Docker Desktop:
1. En **Images**, sobre esa imagen, pulsen **Run**.
2. Abran **Optional settings** y en el puerto escriban `8000`.
3. Pulsen **Run**.
4. Abran http://localhost:8000/docs y prueben `/predict` con **Try it out › Execute**.

Para detenerla, usen el botón de detener en **Containers**.

### 7. Comprobar que se actualiza sola
1. Desde `entrega/e4`, creen una rama nueva con el menú de ramas.
2. Abran `api/app.py`, pulsen el lápiz (**Edit this file**), cambien el `title` de `FastAPI` y pulsen **Commit changes...**.
3. Abran el PR hacia `entrega/e4`. Otro integrante aprueba y hace el merge.
4. Cuando **CD** quede en verde, detengan el contenedor y repitan el paso 6: en `/docs` debe aparecer el título nuevo.

### 8. Entrega del E4
El E4 se termina en el taller del viernes del fin de semana 3. Cuando el checklist de [docs/entregas.md](https://github.com/srobles5/mlops-plantilla/blob/master/docs/entregas.md) esté completo, abran el PR con `base: master` ← `compare: entrega/e4`.

## Listo cuando
- [ ] El workflow **CD** queda en verde con un merge.
- [ ] La imagen aparece en **Packages** del repositorio y es pública.
- [ ] Otro integrante la trae y la corre en Docker Desktop.
- [ ] `/predict` da una predicción desde esa imagen.
- [ ] Los tokens están en GitHub Secrets y en ningún archivo.

## Errores frecuentes
- **`Unable to find the remote` o `config file error` en `dvc remote modify`**: el remote no se llama `dagshub` en `.dvc/config`, o ese cambio no está en la rama.
- **`failed to pull data from the cloud`**: falta `dvc push` de quien entrenó, o `DAGSHUB_USER` y `DAGSHUB_TOKEN` están mal.
- **`denied` o `permission_denied` al publicar**: falta el bloque `permissions` en `cd.yml`, o en **Settings › Actions › General** los permisos del workflow son más restrictivos.
- **`denied` o `not found` en `docker pull`**: la imagen sigue privada, falta el paso 5, o el nombre tiene mayúsculas.
- **La API corre pero el navegador no conecta**: no escribieron el puerto en **Optional settings**.
- **Sigue apareciendo la versión anterior**: falta repetir `docker pull`, o el contenedor viejo sigue corriendo.
- **`port is already allocated`**: el puerto está ocupado. Escriban `8001` en **Optional settings** y abran `localhost:8001`.
