# Laboratorio 4 · CD: la API en Hugging Face Spaces

Sábado del fin de semana 2 · 60 min · por equipos · hito E4

## Objetivo
Que un merge despliegue la API en una URL pública, sin pasos manuales.

Hace falta tener el [laboratorio 1](01-dagshub.md) (DagsHub) y el [laboratorio 2](02-api-docker.md) (Docker).

## Pasos

### 0. Rama de trabajo
```bash
git switch entrega/e4
git pull
git switch -c feat/cd-space
```

### 1. Crear el Space (una persona)
1. Creen una cuenta en https://huggingface.co. Es gratis y no pide tarjeta. Una cuenta por equipo basta.
2. **New Space**. Nombre: `api-<equipo>`. **SDK: Docker › Blank**. Hardware gratis y visibilidad pública.
3. Foto de perfil **› Settings › Access Tokens › Create new token**, de tipo **Write**. Copien el token.

### 2. Guardar los secretos
En GitHub, en el repositorio del equipo: **Settings › Secrets and variables › Actions › New repository secret**. Creen tres:

| Nombre | Valor |
|---|---|
| `HF_TOKEN` | El token de Hugging Face |
| `DAGSHUB_USER` | El usuario de DagsHub |
| `DAGSHUB_TOKEN` | El token de DagsHub |

Un token subido a Git queda en el historial aunque lo borren después. Si se filtra uno, revóquenlo y creen otro.

### 3. El encabezado del Space
Creen `space/README.md`, que también está en [la plantilla](https://github.com/srobles5/mlops-plantilla/blob/master/space/README.md):
```markdown
---
title: API del equipo
sdk: docker
app_port: 8000
---
```
Hugging Face espera por defecto el puerto 7860; `app_port` le dice que la API usa el 8000.

### 4. El workflow
Creen `.github/workflows/cd.yml`, que también está en [la plantilla](https://github.com/srobles5/mlops-plantilla/blob/master/labs/FDS2/workflows/cd.yml), cambiando `usuario/api-equipo` por su Space:
```yaml
name: CD
on:
  push:
    branches: [master, entrega/e4]
jobs:
  desplegar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.12"
      - run: pip install dvc huggingface_hub
      - name: Traer el modelo
        run: |
          dvc remote modify dagshub --local auth basic
          dvc remote modify dagshub --local user ${{ secrets.DAGSHUB_USER }}
          dvc remote modify dagshub --local password ${{ secrets.DAGSHUB_TOKEN }}
          dvc pull models/model.pkl
      - name: Subir al Space
        run: |
          cp -r api models Dockerfile requirements-api.txt space/
          hf upload usuario/api-equipo space . --repo-type=space --token=${{ secrets.HF_TOKEN }}
```
`entrega/e4` está en la lista para poder probar el despliegue antes de que el docente una el E4 a `master`. Cuando el E4 se una, pueden quitarla.

### 5. Confirmar el modelo en DagsHub
El modelo no está en Git: el workflow lo trae de DagsHub.
```bash
dvc pull
dvc status -c
```
Si `dvc status -c` muestra archivos pendientes, súbanlos con `dvc push`.

### 6. Pull Request y despliegue
```bash
git add space .github/workflows/cd.yml
git commit -m "Despliega la API en Hugging Face Spaces"
git push -u origin feat/cd-space
```
PR con `base: entrega/e4` ← `compare: feat/cd-space`. Cuando el CI esté en verde, otro integrante aprueba y hace el merge: ese merge dispara el CD. Vean **Actions** y luego la pestaña **Logs** del Space, donde Hugging Face construye la imagen. Tarda unos minutos.

### 7. Probar la URL pública
La dirección es `https://<usuario>-api-<equipo>.hf.space`, en minúsculas.
```bash
curl https://<usuario>-api-<equipo>.hf.space/health
```
Abran `/docs` en esa misma dirección y prueben `/predict`. Un Space gratis se duerme si nadie lo usa: la primera petición puede tardar.

### 8. Comprobar que se actualiza solo
En una rama nueva, cambien el `title` de `FastAPI` en `api/app.py` y abran un PR hacia `entrega/e4`. Después del merge y de la construcción, recarguen `/docs`: debe aparecer el título nuevo.

### 9. Entrega del E4
El E4 se termina en el taller del viernes del fin de semana 3. Cuando el checklist de [docs/entregas.md](../../docs/entregas.md) esté completo, abran el PR con `base: master` ← `compare: entrega/e4`.

## Listo cuando
- [ ] La URL pública responde en `/health`.
- [ ] `/predict` da una predicción desde esa URL.
- [ ] Los tokens están en GitHub Secrets y en ningún archivo.
- [ ] Un merge actualizó la API sin pasos manuales.

## Errores frecuentes
- **`Unable to find the remote` o `config file error` en `dvc remote modify`**: el remote no se llama `dagshub` en `.dvc/config`, o ese cambio no está en la rama.
- **`failed to pull data from the cloud`**: falta `dvc push` de quien entrenó, o `DAGSHUB_USER` y `DAGSHUB_TOKEN` están mal.
- **`401` o `403` en `hf upload`**: el token no es de tipo Write, o el Space no es de esa cuenta.
- **`404` o `Repository Not Found` en `hf upload`**: no han creado el Space o el nombre no coincide.
- **El Space queda en `Configuration error`**: `space/README.md` no empieza con el encabezado entre `---`, o falta `sdk: docker`.
- **El Space queda en `Starting` y nunca abre**: `app_port` no coincide con el puerto del `CMD`.
- **`Permission denied` en los logs del Space**: el contenedor corre con el usuario 1000. La API no debe escribir archivos dentro de `/app`.
- **Hugging Face falla ese día**: Render, en su plan gratis, sirve de respaldo con el mismo Dockerfile.
